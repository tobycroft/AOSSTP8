开放接口文档

本文档说明系统对外接口的访问方式（凭据与鉴权）、链接方式（地址拼装与路由规则）、加密方式（签名与密钥），以及各业务域的接口清单、统一响应结构与证书接口链路。内容按现有代码实现整理。

版本 v1.4 更新 2026-11-16 接口域名 upload.tuuz.cc:433 默认时区 Asia/Shanghai

接口概览

系统对外提供三类接口入口，彼此独立鉴权，令牌不可混用：

开放接口业务系统调用，四段式路径 /{version}/{module}/{controller}/{action}，域名根 upload.tuuz.cc:433。
上传服务独立主机 https://upload.tuuz.cc:433，使用一次性临时令牌，避免长期令牌暴露。
证书下发面向宝塔面板、爱快路由器、Proxmox VE 与宝塔邮局，按证书名称串联拉取与部署。

接口统一返回 JSON（code / data / echo），按 application/x-www-form-urlencoded 或 JSON 字符串提交参数，详见后文各节。

本页与代码同步维护：路由在 route/route.php，鉴权在各模块 initialize()，签名规则在对应控制器内。调整实现时请同步更新本页。

鉴权方式

不同业务域使用不同凭据，凭据在后端配置表中维护，接口侧只做校验：

凭据矩阵

业务域凭据传递方式校验位置
文件 / 短信 / 存储项目令牌（ao_oss.token）文件类：URL 参数 token；短信：POST 参数 nameOssModel::api_find_token
证书管理appname + appkey（ao_cert）GET / POST 参数/v1/cert/* 初始化
AI 能力项目 Secret（ao_v3_project.secret，服务端签发的 64 位随机串），同时作为信封加密密钥请求头 X-Aoss-Ts / X-Aoss-Kid / X-Aoss-Auth，secret 不出现在请求中V3ProjectModel::api_find_kid + Aoss\Envelope::open
抖店appid + appsecret + salt + sign，或 tokenPOST / GET 参数/v2/doudian/* 初始化
上传服务一次性临时令牌URL 参数 tokenao_file_token
令牌即身份，请勿写入前端源码或公开仓库。证书接口的 appkey 泄露等同于该证书项目的全部下发权限。

上传临时令牌

上传使用独立主机与端口，先用项目令牌换取短时令牌，再用令牌上传：

  1. 换取令牌：POST https://upload.tuuz.cc:433/v2/file/index/token，参数 token（项目令牌）、timestamp（秒级时间戳）、sign、可选 ip。
  2. 执行上传：https://upload.tuuz.cc:433/v2/file/index/upfull?token={临时令牌} 返回完整文件信息；uphash 仅返回 MD5，需再调 POST /v2/file/token/hash_query 取得文件详情。

临时令牌默认 300 秒过期，写入 ao_file_token 并以 is_used 标记一次性使用；返回值中的 upload_url 与 upload_url_hash 可直接用于上传。

请求头与跨域

  • 全局响应跨域头：Access-Control-Allow-Origin: *、Allow-Methods: GET, POST, PATCH, PUT, DELETE, OPTIONS、Allow-Headers: *、Max-Age: 86400。
  • 预检请求 OPTIONS 由路由前置中间件直接放行，不进入业务逻辑。
  • 普通接口按 application/x-www-form-urlencoded 提交；AI 的 messages、tools 等结构化字段以 JSON 字符串提交，由 Input::PostJson 解析。

链接规则

四段式路由

开放接口采用「版本 / 模块 / 控制器 / 方法」四段式路径，由 route/route.php 的兜底规则统一解析：

URLhttps://{host}/{version}/{module}/{controller}/{action}
PHP// route/route.php
Route::any(':version/:module/:controller/:function',
    '\app\:version\:module\controller\:controller@:function');

映射到物理文件 app/{version}/{module}/controller/{controller}.php 的 {action} 方法。未命中任何规则的请求由兜底闭包原样返回请求 URL。

该规则固定四段路径，控制器默认方法需显式写出：/v3/ai/responses/index 可命中，省略 /index 的三段路径不会命中任何规则。

参数约定

  • 参数名大小写敏感，布尔值统一使用 1 / 0。
  • 列表分页参数为 page（从 1 开始）与 search，每页 15 条。
  • 时间戳统一为秒级 Unix 时间，服务端时区 Asia/Shanghai。
  • 证书接口的 cert 同时作为业务主键，需与 ao_cert_url.cert 完全一致。

推理模式（Thinking）

三个文本接口均兼容「带推理」与「不带推理」两种模式：不传推理开关即为不带推理（默认）；按下表传入对应字段即开启带推理。两类字段不可混用——chat_template_kwargs 属于 OpenAI 兼容格式，thinking 属于 Anthropic 兼容格式。

接口格式开启推理（JSON 字符串提交）
chat/completions、responsesOpenAIchat_template_kwargs={"enable_thinking":true}
messagesAnthropicthinking={"type":"enabled","budget_tokens":2048}
 
cURL# 带推理：chat/completions（OpenAI 格式）
curl -s https://upload.tuuz.cc:433/v3/ai/chat/completions \
  -H "X-Aoss-Ts: $TS" -H "X-Aoss-Kid: $KID" -H "X-Aoss-Auth: $AUTH" \
  --data-urlencode 'messages=[{"role":"user","content":"规划这个仓库任务的实现步骤"}]' \
  --data-urlencode 'chat_template_kwargs={"enable_thinking":true}'

# 带推理：messages（Anthropic 格式）
curl -s https://upload.tuuz.cc:433/v3/ai/messages/index \

  --data-urlencode 'messages=[{"role":"user","content":"规划这个仓库任务的实现步骤"}]' \

门户登录与注册

门户（console）的登录与注册接口位于域名根路径，不使用四段式路由；两者共用验证码图片接口 GET /captcha/gif（4 位数字，答案 hash 写入 cookie user_captcha，有效期 300 秒）。

登录验证码策略

登录验证码按 IP 自适应：无失败记录时默认不需要验证码；一旦该 IP 登录失败 ≥1 次，在 2 小时窗口内（每次失败重新计时）强制校验验证码；任意一次登录成功立即解除，下次登录恢复免验证码。失败状态存于数据表 ao_login_fail（每个 IP 一行，登录成功即删除），建表脚本见 sql/20261116_create_ao_login_fail.sql。

能力方法与链接关键参数
登录POST /loginusername, password, code（code 仅在需要验证码时必填）
登录态GET /login/infouser_token（cookie 或请求头）
退出POST /login/logoutuser_token
失败响应 data 字段含义
need_captcha: true该 IP 已进入验证码强制状态，前端需展示验证码并随下一次提交带上 code
need_captcha: false未触发验证码策略（含状态表不可用时的降级）

注册

注册始终强制验证码，不受上述 IP 失败策略影响；邀请码为必填，注册页默认填入 tuuz。

能力方法与链接关键参数

签名与加密

传输加密

所有对外生产入口强制 HTTPS：开放接口与上传服务 upload.tuuz.cc:433、图片服务 image.tuuz.cc:433。除 v3 的凭证信封外，其余接口以传输层加密与访问控制为主，未启用应用层加密。

v3 凭证信封

v3 接口不存在「项目 token」这一概念：ao_ai.name 只是人类可读标签，ao_ai.secret 是服务端签发的唯一凭证（64 位十六进制，32 字节熵），同时作为信封加密密钥。调用方据此派生密钥，将「secret|ts」加密为单段密文提交，服务端解密后校验。请求链路上只出现 secret 的哈希前缀与密文，凭证全程不落 URL、请求体与访问日志。

字段内容说明
X-Aoss-Ts秒级 Unix 时间戳，每次请求动态生成与服务端偏差超过 300 秒即拒绝
X-Aoss-Kidsubstr(sha256(secret), 0, 8)仅用于服务端定位记录，不可逆推 secret
X-Aoss-Authv1.base64url(iv ‖ ciphertext ‖ tag)AES-256-GCM 密文，明文为 secret|ts
  • 密钥派生：key = hash_hkdf('sha256', secret, 32, 'aoss.v3.envelope')，与记录一一对应，更换 secret 即更换密钥。
  • IV 每次随机 12 字节，同一 secret 的密文逐次不同；GCM 认证标签保证密文不可篡改；版本号 v1 同时作为 AAD 绑定。
  • 服务端依次校验：时间窗 → kid 定位记录 → 解密并验证标签 → 密文内 secret 与记录完全一致 → 内层 ts 与外层一致 → 状态启用。
  • 服务端实现：extend/Aoss/Envelope.php；调用方可直接复用该类的 seal() 方法。
PHPuse Aoss\Envelope;

$secret = '项目Secret';  // ao_ai.secret，后台「复制」取得，同时是加密密钥
$ts     = time();

$headers = [
    'X-Aoss-Ts'   => (string)$ts,
    'X-Aoss-Kid'  => Envelope::kid($secret),
    'X-Aoss-Auth' => Envelope::seal($secret, $ts),
];

// POST https://upload.tuuz.cc:433/v3/ai/chat/completions
// body: messages=[{"role":"user","content":"你好"}]
cURLTS=$(date +%s)
# AUTH 由 Envelope::seal($secret, $ts) 生成
curl -s https://upload.tuuz.cc:433/v3/ai/chat/completions \
  -H "X-Aoss-Ts: $TS" \
  -H "X-Aoss-Kid: 9f2c1a7b" \
  -H "X-Aoss-Auth: v1.xxxxxxxx" \
  -d 'messages=[{"role":"user","content":"你好"}]'
时间窗依赖服务端时钟，客户端需启用 NTP；返回 401 且 data.server_time 有值时，按该值校准客户端时间。secret 泄露时在后台「agnes」点击「重置Secret」，旧 secret 与旧 kid 立即失效，调用方需重新分发。
secret 由服务端签发，不接受人工指定——信封的机密性上限等于 secret 的熵，64 位十六进制（32 字节）是强制格式。信封只保证凭证不落地明文与不可篡改；相同的 auth 在 300 秒窗口内理论上可被重放一次，若需彻底封堵，应在网关层叠加请求去重。

MD5 签名

现有三处签名统一为小写 32 位 MD5，用于防篡改与防重放，不承担加密职责：

场景签名公式时效校验位置
短信单发sign = md5(code + ts)无强制窗口，由业务侧控制/v1/sms/single
上传临时令牌sign = md5(token + timestamp)±300 秒，令牌 300 秒过期/v2/file/token
抖店sign = md5(appid+appsecret+salt)salt 由调用方随机生成/v2/doudian
 
PHP// 短信：code 为 ao_oss 项目密钥，ts 为秒级时间戳
$ts   = time();
$sign = md5($project['code'] . $ts);

// 上传临时令牌
$timestamp = time();
$sign      = md5($projectToken . $timestamp);
MD5 仅用于签名校验。拼接顺序、大小写与是否补零必须严格一致，否则返回 401 签名不正确。时间戳校验依赖服务器时钟，部署时请启用 NTP 同步。

RSA 签名

/v1/rsa/index/index 与 /v1/rsa/index/index2 提供 SHA256 摘要、openssl_sign 签名（Base64 输出）与 openssl_verify 验签能力。当前公私钥为占位常量，需替换为实际 PEM 后使用；该能力属于预留组件，不参与现有接口鉴权。

证书私钥

  • 证书全文与私钥保存在 ao_cert_url.publickey / privatekey，来源为 url_crt / url_key 指向的 HTTP(S) 链接。
  • 宝塔 API 密钥（bt_key）、爱快账号密码、PVE API Token 均以明文存储在对应配置表，仅通过后台管理，不下发到接口响应中。
私钥泄露等同于证书被完全接管。请限定 appkey 的发放范围，并定期轮换宝塔 API 密钥与 PVE Token。

响应与错误码

接口统一返回 JSON：

JSON{
  "code": 0,
  "data": {},
  "echo": "成功"
}
code含义典型场景
0成功业务正常返回，数据在 data
-1登录失效后台令牌无效，前端跳转登录
400参数错误缺少必填参数、长度或格式不符
401鉴权失败令牌不存在、签名不正确、自动下发未启用
403权限不足账号或项目被禁用、拒绝的操作
404未找到数据证书项目、站点或记录不存在
406 / 407数据不符合期待上下游返回结构异常
500服务端错误数据库异常、上游接口调用失败

echo 为可直接展示的中文提示；data 在失败时通常为空数组或错误明细。

绑定规则

站点与证书通过 cert_name 关联，绑定策略如下（忽略大小写、剥离 *. 前缀与结尾点）：

  1. 取站点域名的主域名，即末两段：124.tuuz.ltd → tuuz.ltd、aria.aerofsx.com → aerofsx.com。
  2. 若 ao_cert_url 中存在与主域名完全同名的证书，则绑定该证书名称。
  3. 否则绑定主域名本身（即使该名称暂无对应证书），由后续人工或自动补录。
  4. 子域名证书（shop.example.com）不视为覆盖根域名（example.com），避免误绑定。
  5. 查询站点时同时匹配证书名与规整名两种取值，兼容历史以根域名写入的数据。

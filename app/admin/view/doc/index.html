AOSS 平台使用文档

本页整理当前系统的三种核心接入信息：链接方式（请求地址如何拼装）、加密方式（签名与密钥）、访问方式（凭据与鉴权）。内容依据现有代码实现整理，适用于后台管理、开放接口与证书下发三条链路。

版本 v1.0 更新 2026-11-16 后台域名 aoss.tuuz.cc 默认时区 Asia/Shanghai

概览

系统对外提供三类入口，彼此独立鉴权，请勿混用令牌：

后台管理面向管理员，固定路径 /admin/...，使用登录令牌 admin-token。
开放接口面向业务系统，统一路径 /{version}/.../{action}，使用项目令牌或 appname+appkey。
证书下发面向宝塔面板、爱快路由器、Proxmox VE，按证书名称串联拉取与部署。
本页与代码同步维护：路由在 route/route.php，鉴权在 app/admin/utils/AdminAuth.php 与各模块 initialize()，签名规则在对应控制器内。调整上述实现时请同步更新本页。

访问方式

后台管理

后台通过域名绑定开放，仅 aoss.tuuz.cc 主机头可命中管理路由，域名根路径直接进入后台首页。

  • 登录页：https://aoss.tuuz.cc/admin/login
  • 验证码：先请求 /admin/captcha/gif 获取图形码，验证码哈希写入 admin_captcha Cookie。
  • 登录提交：POST /admin/login/index，参数 username、password、code。
  • 令牌下发：登录成功返回 64 位十六进制 token，服务端写入 ao_admin_user.token，同时写入 admin_token Cookie（有效期 24 小时）。

后续请求可任选一种方式携带令牌，服务端按以下顺序读取：

携带方式写法说明
请求头admin-token: {登录令牌}推荐，AJAX 统一使用
Cookieadmin_token={登录令牌}登录后自动写入
请求参数admin_token={登录令牌}兼容表单直传

所有后台控制器在 initialize() 中调用 AdminAuth::requireLogin()：GET 请求未登录直接跳转登录页，非 GET 请求返回 {"code":-1}，前端拦截到 -1 后清理令牌并跳转 /admin/login。

业务域凭据传递方式校验位置

令牌即身份，请勿写入前端源码或公开仓库。证书接口的 appkey 泄露等同于该证书项目的全部下发权限。

上传服务

上传使用独立主机与端口，避免 OSS 长期令牌暴露：

  1. 换取临时令牌：POST https://upload.tuuz.cc:433/v2/file/index/token，参数 token（项目令牌）、timestamp（秒级时间戳）、sign、可选 ip。
  2. 使用令牌上传：https://upload.tuuz.cc:433/v2/file/index/upfull?token={临时令牌} 返回完整文件信息；uphash 仅返回 MD5，需再调 POST /v2/file/token/hash_query 取得文件详情。

临时令牌默认 300 秒过期，写入 ao_file_token 并以 is_used 标记一次性使用；upload_url 与 upload_url_hash 会在返回值中直接给出上传地址。

请求头与跨域

  • 全局响应跨域头：Access-Control-Allow-Origin: *、Allow-Methods: GET, POST, PATCH, PUT, DELETE, OPTIONS、Allow-Headers: *、Max-Age: 86400。
  • 预检请求 OPTIONS 由路由前置中间件直接放行，不进入业务逻辑。
  • 普通接口按 application/x-www-form-urlencoded 提交；AI 的 messages、tools 等结构化字段以 JSON 字符串提交，由 Input::PostJson 解析。

链接方式

路由规则

开放接口采用「版本 / 模块 / 控制器 / 方法」四段式路径，由 route/route.php 的兜底规则统一解析：

URLhttps://{host}/{version}/{module}/{controller}/{action}
PHP// route/route.php
Route::any(':version/:module/:controller/:function',
    '\app\:version\:module\controller\:controller@:function');

映射到物理文件 app/{version}/{module}/controller/{controller}.php 的 {action} 方法。未命中任何规则的请求由兜底闭包原样返回请求 URL。

该规则固定四段路径，控制器默认方法需显式写出：/v3/ai/responses/index 可命中，省略 /index 的三段路径不会命中任何规则。

后台管理不使用兜底规则，全部为显式注册的固定路径；同一路径按 HTTP 方法分派：

方法语义示例
GET列表 / 详情页GET /admin/cert_url
POST更新记录POST /admin/cert_url + id
PUT新增记录PUT /admin/cert_url
DELETE删除记录DELETE /admin/cert_url + id

参数约定

  • 参数名大小写敏感，布尔值统一使用 1 / 0。
  • 列表分页参数为 page（从 1 开始）与 search，每页 15 条。
  • 时间戳统一为秒级 Unix 时间，服务端时区 Asia/Shanghai。
  • 路径参数在证书接口中同时作为业务主键使用（如 cert），需与 ao_cert_url.cert 完全一致。

加密方式

传输加密

所有生产入口强制 HTTPS：管理后台 aoss.tuuz.cc、上传服务 upload.tuuz.cc:433、图片服务 image.tuuz.cc:444。系统未启用应用层对称加密（无 AES 封装），敏感数据依赖传输层加密与访问控制。

MD5 签名

现有三处签名统一为小写 32 位 MD5，用于防篡改与防重放，不承担加密职责：

场景签名公式时效校验位置
短信单发sign = md5(code + ts)无强制窗口，由业务侧控制/v1/sms/single
上传临时令牌sign = md5(token + timestamp)±300 秒，令牌 300 秒过期/v2/file/token
抖店sign = md5(appid+appsecret+salt)salt 由调用方随机生成/v2/doudian
 
PHP// 短信：code 为 ao_oss 项目密钥，ts 为秒级时间戳
$ts   = time();
$sign = md5($project['code'] . $ts);

// 上传临时令牌
$timestamp = time();
$sign      = md5($projectToken . $timestamp);
MD5 仅用于签名校验。拼接顺序、大小写与是否补零必须严格一致，否则返回 401 签名不正确。时间戳校验依赖服务器时钟，部署时请启用 NTP 同步。

RSA 签名

/v1/rsa/index/index 与 /v1/rsa/index/index2 提供 SHA256 摘要、openssl_sign 签名（Base64 输出）与 openssl_verify 验签能力。当前公私钥为占位常量，需替换为实际 PEM 后使用；该能力属于预留组件，不参与现有接口鉴权。

口令与验证码

  • 用户密码使用 password_hash(PASSWORD_DEFAULT) 存储，登录以 password_verify 校验，数据库不保存明文。
  • 图形验证码以 password_hash 结果写入 admin_captcha Cookie，比对时统一转小写，校验后立即清除。
  • 后台登录令牌为 bin2hex(random_bytes(32)) 生成的 64 位十六进制串，登出时服务端令牌清空。

证书与私钥

  • 证书全文与私钥保存在 ao_cert_url.publickey / privatekey，来源为 url_crt / url_key 指向的 HTTP(S) 链接。
  • 后台读取接口：POST /admin/cert_url/getKey，参数 id，需登录；返回明文证书与私钥，前端不得落盘或写入日志。
  • 宝塔 API 密钥（bt_key）、爱快账号密码、PVE API Token 均以明文存储在对应配置表中，仅通过后台管理，不下发到前端页面。
私钥泄露等同于证书被完全接管。建议限制 getKey 的调用角色，并定期轮换宝塔 API 密钥与 PVE Token。

响应与错误码

除后台页面渲染（HTML）外，接口统一返回 JSON：

JSON{
  "code": 0,
  "data": {},
  "echo": "成功"
}
code含义典型场景
0成功业务正常返回，数据在 data
-1登录失效后台令牌无效，前端跳转登录
400参数错误缺少必填参数、长度或格式不符
401鉴权失败令牌不存在、签名不正确、自动下发未启用
403权限不足账号禁用、拒绝的操作
404未找到数据证书项目、站点或记录不存在
406 / 407数据不符合期待上下游返回结构异常
500服务端错误数据库异常、上游接口调用失败

echo 为可直接展示的中文提示；data 在失败时通常为空数组或错误明细。

证书链接与缓存

  1. url_crt / url_key 保存证书与私钥的下载链接，服务端使用 file_get_contents 拉取，因此必须是服务器可访问的 HTTP(S) 地址（自签证书或需鉴权的地址会失败）。
  2. 单条刷新：POST /admin/cert_url/updateSSL（参数 id）；全量刷新：POST /admin/cert_url/updateAllSSL。
  3. 下发前会先尝试刷新一次证书，刷新失败则沿用数据库中已缓存的 publickey / privatekey，避免上游短暂不可用导致下发中断。

站点绑定规则

站点与证书通过 cert_name 关联，绑定策略如下（忽略大小写、剥离 *. 前缀与结尾点）：

  1. 取站点域名的主域名，即末两段：124.tuuz.ltd → tuuz.ltd、aria.aerofsx.com → aerofsx.com。
  2. 若 ao_cert_url 中存在与主域名完全同名的证书，则绑定该证书名称。
  3. 否则绑定主域名本身（即使该名称暂无对应证书），由后续人工或自动补录。
  4. 子域名证书（shop.example.com）不视为覆盖根域名（example.com），避免误绑定。
  5. 查询站点时同时匹配证书名与规整名两种取值，兼容历史以根域名写入的数据。

运维与安全建议

  • 关闭调试模式：上线前确认 .env 中 APP_DEBUG=false，避免异常堆栈暴露路径与 SQL。
  • 时钟同步：签名与令牌均依赖时间戳，服务器需启用 NTP；时钟偏差超过 300 秒会导致上传令牌校验失败。
  • 跨域收敛：当前 Allow-Origin: * 与 Allow-Credentials: true 同时开启，浏览器会忽略凭证跨域请求；如前端独立部署，建议改为域名白名单。
  • 签名强度：MD5 仅适合防误传，建议后续接口迁移至 HMAC-SHA256 并加入随机数与重放缓存。
  • 权限最小化：getKey、证书下发、updateAllSSL 属于高危操作，应仅对受信管理员开放。
  • 日志留存：ao_cert_log 记录下发结果与上游返回片段，排障时优先查看该表。
